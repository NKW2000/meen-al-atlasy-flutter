# مين الأطليسي

لعبة أسئلة عائلية على غرار Family Feud — مضيف واحد وفريقين، كل لاعب على
جهازه، بيتصلوا **عبر الواي فاي المحلي أو نقطة اتصال المضيف**، بدون سيرفر
وبدون إنترنت وبدون أي صلاحيات.

هاي نسخة Flutter من التطبيق الأصلي (Kotlin/Compose) — نفس القواعد ونفس
الشاشات ونفس الحركة، مع استبدال Nearby Connections بمقابس واي فاي عادية.

## كيف بتشتغل

- **جهاز المضيف** بيعرض السؤال واللوح وبيحكم صح/غلط. هو مصدر الحقيقة
  الوحيد: المحرّك بيشتغل عنده بس، وكل جهاز لاعب بيستقبل «لقطة» من الحالة.
- **كل لاعب على جهازه**. الجهاز ما بيوصله نص السؤال ولا نصوص الأجوبة
  المخفية أصلاً — اللاعب بيسمع السؤال من المضيف، وبيشوف اللوح بأرقام
  الخانات بس لحد ما يكشفها المضيف.
- **بالمواجهة** شاشة اللاعب اللي عالمنصة هي زر كبير — أول ضغطة بتجاوب.
- **باللعب** ما في كبسة: اللاعب بيحكي جوابه والمضيف بيحكم، والعدّاد بيمشي
  وما بيوقف — إذا ما لحق يجاوب بتنحسب غلط.

التطبيق بيشتغل بالوضعين الأفقي والطولي، والواجهة RTL بالكامل والأرقام
هندية عربية. كل شاشة مضبوطة تخلص بشاشة وحدة (بس إعدادات المضيف بتتمرّر)،
والخلفية بتوصل تحت النتش والمحتوى لأ.

## قواعد اللعب (نفس البرنامج)

كل جولة بتمشي هيك:

1. **المواجهة** — كل لاعب إله **رقم** بفريقه لما ينضم (١، ٢، ٣...)، ورقم
   بيواجه نفس الرقم بالفريق التاني. الرقم اللي عليه الدور بس هو اللي شاشته
   بتصير زر. الرقم بيزيد كل جولة. ما في وقت قبل الضغطة؛ أول واحد يضغط
   بيبلّش وقت الجواب عنده (إعداد «ثواني الجواب») — ما لحق يجاوب ← بينحسب
   غلط والدور بينتقل للخصم بوقت كامل. اللي ضغط بيجاوب:
   - جاب الجواب رقم ١ ← فريقه بياخد اللوح فوراً.
   - جاب جواب أقل ← لاعب المنصة التاني بياخد فرصة؛ الأعلى بياخد اللوح.
   - غلط ← الدور بينتقل للفريق التاني. غلطوا الاتنين ← الزر بيرجع يفتح.
2. **العب أو تمرير** — الفائز بالمواجهة بيقرر من جهازه (بابين بينزلقوا
   وشريط وقت ذهبي). ما قرر بالوقت ← بيلعب.
3. **اللعب** — الفريق صاحب اللوح بيجاوب **لاعب ورا لاعب بالدور**: اللي جاوب
   (صح أو غلط) ما بيرجع دوره إلا لما يخلّصوا كل زمايله. كل غلط = X، وبثلاث X
   (إعداد) بتنفتح فرصة السرقة.
4. **السرقة** — لاعب المنصة من الفريق المقابل عنده محاولة وحدة: صحّت ←
   بياخد كل نقاط الجولة، غلطت ← النقاط بترجع للفريق الأول.
5. **النقاط** — نقاط الجولة (pot) بتتجمّع من كل جواب مكشوف، وبتتضرب بمضاعف
   الجولة (`1, 1, 2, 3` افتراضياً) وبتروح **لفريق واحد بس** بنهاية الجولة.
   بين الجولات بتطلع لوحة النتيجة عند الكل، وبنهاية اللعبة النتيجة النهائية.

## مسار اللعبة

1. **المضيف** يضغط «استضافة لعبة» ← **إعدادات المضيف**: اسم الغرفة، أسماء
   الفريقين، عدد الجولات ومضاعف كل جولة، ثواني الجواب،
   ثواني «العب أو تمرير»، عدد الأخطاء اللي بتفتح السرقة، و**تصفية الأسئلة**
   (عدد الأجوبة). بعدها «كمّل للوبي» — اللوبي بيبني اللعبة من هالإعدادات
   بالضبط، واللاعبين بيشوفوا أسماء الفرق اللي سمّاها المضيف.
2. باللوبي المضيف يضغط «بدء البث» — الغرفة بتصير ظاهرة على الشبكة، وبيبيّن
   عنوان الواي فاي تبعه وسطر «لازم الكل يكون على نفس الواي فاي أو نقطة
   اتصال المضيف».
3. **اللاعب** يضغط «انضمام كلاعب» ويكتب اسمه ← **لستة الغرف** القريبة ←
   بيختار غرفة المضيف. أول ما يفوت بيشوف الفريقين بأسماء المضيف وبيدوس على
   الفريق اللي بدّه — بيقدر يبدّل لحد ما تبلّش اللعبة، والمضيف كمان بيقدر
   ينقله بزر «بدّل ⇄».
4. المضيف يضغط «ابدأ اللعبة» (بدو لاعب واحد عالأقل بكل فريق)، وبعدها كل شي
   بيمشي من لوح المضيف: افتتاحية الجولة عند الكل، المواجهة، اللعب، السرقة،
   «اكشف الباقي»، الجولة الجاية.
5. بنهاية اللعبة: «رجوع للوبي» بيبلّش لعبة جديدة بنفس اللاعبين (نقاط
   وأسئلة من الصفر)، و«الرئيسية» بتسكّر الغرفة عند الكل.

الإعدادات من الشاشة الرئيسية فيها **استيراد بنك الأسئلة** وبس؛ باقي
إعدادات اللعبة عند المضيف. شكل ملف البنك وبرومبت جاهز لتوليده بالذكاء
الاصطناعي: [docs/question-bank.md](docs/question-bank.md).

## الشبكة (كيف بيلاقوا بعض)

| | |
|---|---|
| المضيف | خادم WebSocket على المنفذ `47215` (أو منفذ عشوائي إذا كان محجوز) |
| الإعلان عن الغرفة | منارة UDP كل ثانية على المنفذ `47216`: بثّ عام + بثّ موجّه لكل واجهة واي فاي/نقطة اتصال، مع معرّف جلسة عشوائي |
| اللاعب | بيسمع المنارة وبيعرض الغرف (بتختفي بعد ٦ ثواني من آخر بثّ)، وبيتصل بالغرفة اللي بيختارها |
| الرسائل | JSON: `join` / `team` / `buzz` / `choice` من اللاعب، و`state` / `assigned` من المضيف — نفس بروتوكول التطبيق الأصلي |
| الانقطاع | اللاعب بيحتفظ بمعرّفه ومقعده؛ «ارجع لللعبة» بيرجّعه لنفس مكانه. المضيف بيعلّمه «منقطع» وبيتخطّاه بالدور |
| الطلوع | «اطلع وابدأ من جديد» بيقطع الاتصال وبينسى الغرفة والمقعد (الاسم بيضل). طلوع المضيف من اللعبة بيسكّر الخادم عند الكل |

بيشتغل على أي واي فاي منزلي، وعلى **نقطة اتصال المضيف** بدون إنترنت.
شبكات الجامعات/الفنادق اللي بتعزل الأجهزة عن بعض (client isolation) ما
بتنفع — استعمل نقطة اتصال.

## الأصوات والاهتزاز

كل جهاز بيشغّل الصوت لحاله من تغيّر الحالة (نفس القواعد عند المضيف
وعند اللاعبين): كشف جواب، X (لكل رقم صوته)، غلط بالمواجهة، فوز الجولة،
ودقّات آخر خمس ثواني. بالسرقة: غلط الفريق التاني = صوت الغلط، وصحّه = صوت
الكشف. ضغطة الزر بالمواجهة بتشغّل صوتها واهتزازها فوراً من جهاز اللاعب.
الملفات بـ `assets/sounds/` (نفس ملفات التطبيق الأصلي).

## بنية المشروع

```
lib/
  game/        محرّك القواعد — Dart خالص بدون Flutter (models, events, engine, settings)
  network/     خادم المضيف (WebSocket)، المنارة والبحث (UDP)، عميل اللاعب، الرسائل
  questions/   بنك الأسئلة: القارئ والمدقّق والمخزن، والبنك المرفق
  app/         المتحكّمان (HostController / PlayerController) ومستودع الإعدادات
  feedback/    الأصوات والاهتزاز وقواعد التنبيه (cuesFor)
  ui/          الثيم، الحركة (show_motion)، المكوّنات المشتركة، والشاشات:
               intro / home / settings / host / player / show
  demo/        معرض الشاشات (نسخة الديمو)
  main.dart    الإقلاع وخريطة التنقّل
assets/        الخطوط، الأصوات، والبنك المرفق (starter_questions.json)
test/          ~٣٠٠ اختبار: المحرّك (منقول بالكامل من الأصل)، الشبكة (loopback)،
               البنك، المتحكّمات، وويدجت لكل شاشة بالوضعين وعلى موبايل بنوتش
android/       مشروع أندرويد: نكهتان game / demo، التوقيع، قناة قفل الـ multicast
docs/          التصميم، بنك الأسئلة، قائمة الاختبار اليدوي، ومواصفة/خطة النقل
```

`lib/game/` مقصود يضل بدون أي `import 'package:flutter'` حتى يضل قابل
لاختبار وحدة كامل بدون جهاز.

## البناء والاختبار

بتحتاج Flutter 3.47 (Dart 3.13)، JDK 17+، وAndroid SDK (platform 36،
build-tools 36، NDK 28.2).

```bash
flutter pub get
flutter test                              # كل الاختبارات
flutter analyze
flutter build apk --release --flavor game # اللعبة   → build/app/outputs/flutter-apk/app-game-release.apk
flutter build apk --release --flavor demo --dart-define=DEMO=true   # الديمو → app-demo-release.apk
flutter run --flavor game                 # على جهاز موصول
```

اختبار البحث عن الغرف (UDP على loopback) بينتخطّى تلقائياً على CI.

## نسخة الديمو (معرض الشاشات)

للتجربة على الواجهات بجهاز واحد بدون شبكة: نكهة `demo` مع
`--dart-define=DEMO=true` بتفتح على معرض بيعرض كل شاشة باللعبة (١٩ شاشة)
بحالة مزيّفة — التنقّل من السهمين اللي تحت. بتنركّب **جنب** اللعبة (معرّفها
`com.feudparty.app.demo` واسمها «مين الأطليسي — ديمو»). الشاشات نفسها هي
شاشات اللعبة الحقيقية، بس بدون منطق.

## التوقيع والنشر

كل وسم (tag) بصيغة `v*` بيشغّل
[ورك‌فلو الإصدار](.github/workflows/release.yml): اختبارات، بناء اللعبة
والديمو، ونشرهن كـ Release مع الـ APK‌ين. وسم فيه شرطة (`v0.7.0-alpha.3`)
بينشر كنسخة تجريبية. كل دفعة على `main` بتشغّل الاختبارات والبناء بدون نشر.

```bash
git tag -a v0.8.0 -m "..."
git push origin v0.8.0
```

رقم النسخة بـ `pubspec.yaml` (`version: 0.7.4+30`).

**التوقيع:** التحديث ما بيتركّب فوق نسخة قديمة إلا إذا كان الاتنين موقّعين
بنفس المفتاح. المفتاح بيجي من `android/key.properties` (مش بالمستودع):

```properties
storeFile=/path/to/meen-al-atlasy-release.jks
storePassword=...
keyPassword=...
keyAlias=meen
```

وعلى GitHub من أسرار المستودع `ANDROID_KEYSTORE_BASE64` (الملف مشفّر
base64)، `ANDROID_KEYSTORE_PASSWORD`، و`ANDROID_KEY_ALIAS`. بدونهم البناء
بيوقّع بمفتاح debug مؤقت (وبيحذّر بسجل الورك‌فلو). **لا تضيّع المفتاح** —
بدونه ما في تحديث لأي نسخة منشورة.

## المتطلبات

- أندرويد ٨.٠ (API 26) أو أحدث
- واي فاي مشترك أو نقطة اتصال من المضيف — **بدون** إنترنت وبدون Google
  Play Services وبدون أي صلاحية بتطلب موافقة (بس `INTERNET` وقفل الـ
  multicast، وبينمنحوا تلقائياً)
- أول تركيب بدّه تسمح بـ«مصادر غير معروفة» لأنه التطبيق مش عالمتجر
